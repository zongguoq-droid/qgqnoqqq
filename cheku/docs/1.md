## gps_daemon — GPS 定位进程

【已有代码库】
@src/common

【功能需求】
1. 通过串口 /dev/ttymxc5 (i.MX6ULL 原生 UART5) 读取 GPS 模块 NMEA-0183 数据，波特率 9600/8N1
2. 字符级状态机解析 6 种 NMEA 语句：$GPGGA / $GPRMC / $GPGLL / $GPGSA / $GPGSV / $GPVTG
3. 提取：经纬度、速度(km/h)、UTC时间/日期、卫星数、HDOP、海拔
4. Haversine 公式里程累计，过滤 <1m 漂移
5. UNIX Socket 服务端 /tmp/car_gps.sock，每秒推送 gps_data_t 给 UI
6. 轨迹日志记录

【技术要求】
1. termios 串口配置：cfmakeraw + cfsetspeed(B9600) + CS8 + 非规范 VMIN=0/VTIME=1
2. NMEA 状态机逐字符解析，不使用 sscanf
3. ringbuffer 缓存串口数据 + epoll/poll 事件驱动
4. CRC8 校验和验证，容错无校验和的廉价 GPS 模块

【实际架构】
- 串口设备: /dev/ttymxc5
- NMEA 校验: 逐字符 XOR 累加，`*` 后 2 位 HEX 比对
- 度分转换: ddmm.mmmm → dd + mm.mmmm/60
- 里程: Haversine 公式，地球半径 6371000m

## input_daemon — 按键输入管理进程

【已有代码库】
@src/common

【功能需求】
1. 监听 /dev/input/event2 (gpio-keys) 的 KEY1/KEY2 按键
2. FSM 手势识别: 短按 / 长按(>2s) / 双击(<500ms)
3. LED: 每次短按 LED0 闪烁一次 (亮 150ms 后自动熄灭，通过 /dev/100ask_led 驱动)
4. UNIX Socket /tmp/car_input.sock，推送 MSG_KEY_EVENT 给 UI

【技术要求】
1. Linux input 子系统: read(fd, &input_event, sizeof(input_event))
2. 按键手势状态机: IDLE→PRESSED→LONG_PRESS/WAIT_DOUBLE→DOUBLE_CLICK
3. LED 驱动接口: write(fd, [led_index, 0/1], 2) (0=亮, 1=灭)
4. poll 模式，50ms tick 驱动状态机

【Qt 按键分发】
- Qt 主线程收到按键事件后，按当前标签页分发功能:
  - DVR 页: KEY1 → 拍照, KEY2 → 暂停/继续录像
  - 音乐页: KEY1 → 播放, KEY2 → 暂停
- 仅短按触发功能，长按(>2s)/双击(<500ms)忽略

【实际硬件】
- 设备树: KEY1→KEY_1(code=2, gpio5-1), KEY2→KEY_2(code=3, gpio4-14)
- 按键设备: /dev/input/event2
- LED 设备: /dev/100ask_led

## av_daemon — 音频播放服务进程

【已有代码库】
@src/common

【功能需求】
1. ALSA PCM 播放 /music/ 下的 WAV 文件 (44100Hz 16-bit 立体声)
2. WM8960 混音控制: Speaker/Headphone 音量
3. 播放列表: 扫描 /music/，启动自动播放第一首，播完自动下一首循环
4. UNIX Socket /tmp/car_av.sock，UI 控制播放/暂停/停止/音量

【技术要求】
1. ALSA: snd_pcm_open("hw:0,0") → snd_pcm_writei 阻塞写入 (和 aplay 一致)
2. WM8960: Left/Right Output Mixer PCM 开关需显式打开，音量 raw 值非线性的映射
3. 整文件读入内存后分块播放，poll 循环同时处理 Socket 和文件轮询
4. 音量/曲目名控制改用文件方式 (/tmp/av_volume、/tmp/av_track)，播放/暂停走 Socket 协议
5. WAV RIFF 格式解析 (44 字节头)

【教训】
- WM8960 音量非线性: raw=0-127, 50%=raw63 已近无声, 需自定义映射
- 二进制帧协议对本地 IPC 是过度设计, 简单文件/文本方式更可靠

【实际硬件】
- card 0: wm8960audio, device 0: HiFi wm8960-hifi-0
- aplay -Dhw:0,0 可正常播放

【已有代码库】
@src/common

【功能需求】
1. V4L2 采集 USB 摄像头 /dev/video1，MJPEG 640x480
2. 每 15 帧更新预览图 /tmp/dvr_preview.jpg 供 Qt UI 显示
3. 启动时自动拍照保存为 /record/<ts>_001.jpg (自动编号)
4. 按键拍照保存到 /record/ 目录，自动递增编号 (如 002, 003...)
5. 循环录像: 60s 分段，超限自动删旧文件
6. 暂停/继续录像: 暂停期间暂停写入，恢复后继续写入同一文件，累计时长追踪

【技术要求】
1. V4L2 mmap 零拷贝: open→QUERYCAP→S_FMT(MJPEG)→REQBUFS(32)→QUERYBUF+mmap→QBUF→STREAMON
2. MJPEG 直存: 帧数据已是 JPEG，直接 fwrite，无需 x264 编码
3. poll 模式: poll([v4l2_fd, server_fd, client_fd], 1000ms)
4. 循环存储: stat 遍历目录，按修改时间删最老文件

【实际配置】
- 摄像头: /dev/video1, USB 2.0 Camera (uvcvideo)
- 存储: /record/，2000MB 上限，60s/段

## 关键技术教训

1. **跨语言二进制对齐**: #pragma pack(1) 必须同时在 C/C++ 两端，且平台相关类型 (time_t) 需替换为固定宽度 (uint32_t)
2. **设备独占**: 字符设备驱动通常只允许一个进程打开
3. **DHT11 轮询特性**: 驱动需持续快速 read，间歇式采样无法获取数据
4. **epoll/timerfd 兼容性**: 内核 4.9.88 + Buildroot 环境改用 poll+signal 更稳定
5. **WM8960 PCM 通路**: Left/Right Output Mixer PCM 开关默认关闭，需显式打开
6. **htons/ntohs 双重反转**: 手动拆分字节时不应再用 htons；小端序平台 (ARM) 先 htons 再强转 uint16_t* 读出，等于做了两次反转，值完全错误。正确做法: 直接 memcpy 或手动组装，不再经过 htons/ntohs
7. **memset 参数别名陷阱**: 函数参数指针若指向被清零结构体内部成员，memset 清空结构体后参数值变随机。必须先 memcpy 保存参数到局部变量，再 memset
8. **CAN 栈垃圾**: SocketCAN 协议接收缓冲区若未 memset 初始化，强转 can_msg_t* 时会读到栈上随机值。每次接收前必须 memset(buf, 0, sizeof(buf))
